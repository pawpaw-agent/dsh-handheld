# 手持端界面注入：已移除

> 2026-11-05 起 **不再有任何界面注入**。本文保留结论与原因，避免以后重复踩坑。

## 现在的做法

手机端直接用 dsh 自带的移动端 UI，App 不做任何页面级改动（不改 DOM、不改 CSS、不注入 JS）。

dsh 0.2.2 起宿主自带：

- 抽屉式侧栏：固定定位、滑入滑出，内容区宽度/位置不变（不跳变）
- 顶栏自带的「打开侧边栏 / 收起侧边栏」开关，无需 App 再造悬浮按钮
- 会话行自带的「归档 / 置顶」按钮（rowQuickActions，默认 display:none，桌面悬停才显示）
- 窄屏下的布局与栅格全部由宿主处理（grid-template-columns 第一列自动置 0）

## 为什么移除

1. **升级兼容性**：注入依赖宿主内部类名与状态模型，宿主升级即失效甚至帮倒忙。真实事故：
   0.2.2 把「关闭」从 collapsed class 改成了 inert 属性，我们的判断逻辑立刻误判，
   把已关闭的面板摆回屏幕内，导致侧栏里的「视图选项 / 添加工作区」两个图标穿到聊天界面上。
2. **宿主已原生实现**：当初注入要解决的问题（抽屉、不位移、开关）宿主全都做了。
3. 注入越长越脆：历史峰值约 7KB，含栅格改写、逐帧同步、合成层优化，全部与宿主内部实现强耦合。

## 历史（仅供追溯）

| 时间 | 变化 |
| --- | --- |
| 2026-10-15 | 曾决定零注入，移除全部注入层 |
| 2026-10-30 | 用户要求在 App 端注入「侧栏 → 悬浮按钮」（宿主当时侧栏不可用） |
| 2026-11-05 | dsh 0.2.2 原生移动端就绪 → 精简到 2KB（全屏 + 行内按钮常显）|
| 2026-11-05 | 用户要求彻底零注入 → 移除全部 |

## 如果以后又想加

先把需求对照宿主现状核实一遍（用无头 Chrome 在 384x832 下零注入实测），
确认宿主真的没有再做；并且优先考虑**不依赖类名**的手段。
