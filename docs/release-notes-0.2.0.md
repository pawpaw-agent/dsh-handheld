# dsh-handheld 0.2.0

> 安装、许可、依赖上限的公共部分见 [`releasing.md`](releasing.md)。本页只写本版差异。

这一版做的是**减法**：把两个已经不成立的东西（手机端注入适配层、原生终端）整体移除，
再把「用起来会被绊到」的几处补上。净减约 1.5 万行。

## 🗑 移除：手机端注入适配层

App 此前会往 dsh 页面里注入一层 158 KB 的 JS（改布局、藏按钮、加自己的抽屉）。

**它已经不可能工作了**：dsh 0.1.7-rc.2 起，客户端加载器会按服务端清单回收注入的插件条目
（`tearDownEntryFiber` + `removeOwnedStyles`）—— 真机取证是「注入成功、样式随即被删、
回合计数恒为 0」。同时 dsh 自己的响应式布局已经够用。

所以整层删除，连带它的引导脚本、契约检查脚本与验证工具。**页面现在是纯 dsh 页面。**

## 🗑 移除：原生终端

dsh 的 web 界面自带终端面板（右栏 → **新建终端**，xterm + WebSocket），WebView 直接可用。
于是 App 侧那套退场：`TuiActivity`、Termux 的额外键条、vendored 的 `com.termux.*` 7 个文件、
`terminal-view` 依赖、`terminal-conformance` 模块与 CI 任务，以及连接屏上
「看网页 / 开终端」那个切换 —— **主按钮从此只做一件事**。

## 🖥 新增：多主机

连接屏顶部现在有独立的**主机卡片**（不用点进折叠表单）：

```
主机
xsj@192.168.0.135                    ▾      ← 首项是「＋ 新建主机…」
[ ＋ 新建主机 ]   [ 保存 ]   [ 删除 ]
```

- 「＋ 新建主机」→ 表单清空，填好地址/账号/密码点「保存」即入库；
- 选已存主机时「保存」是**就地更新**（早先只有一个「存为新主机」，改一下当前主机的密码
  就会多出一条副本 —— 这个毛病一并修了）；
- **切换主机 = 换一台电脑**：自动拆掉旧隧道并连到新主机；
- 密码按主机**分别加密存储**，切回来不用重填；
- **老配置自动迁移**：首次启动会把原来那一条连接变成列表里的第一条，什么都不用重填。

## 🎤 修复：语音输入

App 此前**完全没有麦克风权限链** —— 清单没有 `RECORD_AUDIO`、没有运行时申请、
也没实现 WebView 的 `onPermissionRequest`（默认一律拒绝），所以点麦克风只会得到
「麦克风权限未开启」。现在补全，并且只放行**隧道页面**的音频采集。

## 🔗 修复：消息里的链接点了没反应

dsh 用 `window.open(url, "_blank")` 开外链（聊天里的链接、右栏浏览器面板的
「外部打开」、工具输出里的链接），而 WebView 默认 `supportMultipleWindows=false`
时这类调用**静默失效**。现在这类链接交给系统浏览器；页面里点普通外链也不会把
App 导航走（那样 dsh 页面就没了）。只放行 `http/https`。

## ↩️ 修复：BACK 收起抽屉（适配 dsh 0.2.0）

BACK 阶梯第二级原先找的是 `data-handheld="*"` —— 那是**注入层自己加的**属性，
注入层移除后它永远返回 false。现在改用宿主自己的 `data-sidebar-collapsed` 判据 +
点宿主自己的侧栏开关。

## 🔔 新增：通知里「打开连接屏」

常驻通知多了一个动作。此前从网页回连接屏**只有一条路**：BACK，且要网页没有历史、
没有模态、没有开着的抽屉 —— 日常用着页面时按 BACK 会先走网页历史/抽屉，回不去。

## 🧪 工程

- 补上**单元测试**（配置序列化与旧格式兼容、多主机三条规则、隧道 origin 判定）
  与 CI 的 `test` job —— 这三处都是「错了不报错、只是功能坏掉」的逻辑；
- **随附 dropbear 的许可证文本**：此前它被拷进 `jniLibs/`，而 AGP 只打包那里的 `.so`，
  `.txt` 根本进不了 APK。现在作为 asset 打包，并有 CI 断言守着；
- `targetSdk` 34 → **35**（Android 15 的强制 edge-to-edge，本 App 一直是主动 opt-in 的）；
- 依赖只剩 `androidx.core:core-ktx`（+ 测试期的 JUnit/org.json）。

## 适配的 dsh 版本

本轮按 **dsh 0.2.0-rc.2** 逐项核对了「App 侧要提供什么」：麦克风权限、外链、
文件选择（附件）、剪贴板读写（终端里粘贴）、`visualViewport`（键盘）、iframe 预览 ——
只有前两项需要 App 做事，其余 WebView 自带。`directory-picker-native` 是**宿主侧**的
（注释明说 renders on the host display），App 不需要支持。
