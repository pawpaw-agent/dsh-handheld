**手机端适配 + 通知的一次修复版。** 三件事，都在真机（SM-S9280 / Android 16）上逐条验过：
输入框上方那行统计不再被省略号截断、任务完成通知不再静默失效、完成通知会弹横幅。

## 🔧 输入框上方那行统计：窄屏用满宽度（插件 rev 1.0.19）

原先 384px 的手机上它只有 **288px** 可用 —— 宿主自己左右各 32px（`--dsh-composer-side-clearance`
16px + 16px），而它挂的 composer dock 再各 16px；两个胶囊
（`9 轮 298 步 · 111 tok/s` / `62.6M tok · 缓存命中 98%`）在 13px 下要 ≈349px，于是
**两个都被省略号吃掉一截**，两侧却还空着 32px。真机截图：`111···` / `缓存命···`。

改法（只在 ≤560px 生效）：左右各 12px、两个胶囊分列两端（`space-between`）、字号 11.5px、
分隔符左右 2px、装不下时**换行**而不是省略号。

| | 这一行 |
|---|---|
| 改前（1.0.17） | `11 轮 398 步 · 107 to···` / `89M tok · 缓存命中 9···` |
| 改后（1.0.18） | `11 轮 456 步 · 110 tok/s` / `110M tok · 缓存命中 98%` |

教训也写进了文档：第一版只按视口宽度建模（以为有 360px 可用），小回环全绿、真机照旧截断 ——
漏了父容器那 32px。现在的小回环连父容器一起搭，并把「余量 ≥ 12px」写进断言。

## 🔔 任务完成通知：不再静默失效

用户报「完成后没有收到弹窗提醒」。真机日志显示**不是通知被系统吃掉**，而是页面根本没报结束：
`turn-start` 收到过两次、`turn-done` 只在第一次收到，之后整整一小时没有任何「页面报告」。

根因：判据取 `document.querySelector('[class*="_turnStatus"]')` 的**第一个**节点，而
「对话 / 轨迹」两个面板各挂一份同名节点 —— 隐藏那份 `isConnected` 永远为真，
`running` 卡在 true，此后再也没有「从有到无」的跃迁。
改成「可见的那个」（`isConnected && getClientRects().length > 0`），并加 60s 诊断心跳
（`{"type":"turn-state","nodes":N}`）—— 装上新包第一次心跳就打出 `nodes=2`，坐实了这个判断。

## 🔔 完成通知改成弹横幅

原来那条约只在通知栏里躺着：渠道 `dsh-turn` 建的时候是 `IMPORTANCE_DEFAULT`（3），
而 heads-up 要求 `IMPORTANCE_HIGH`（4）及以上。Android 的渠道重要性**创建之后 App 改不动**
（只有用户能在系统设置里改），所以换 id 重建：`dsh-turn-hi`（HIGH），并删掉旧渠道。
建渠道的时机也提前到 App 启动（开关开着就建），否则「为什么没弹横幅」在第一条通知之前
根本查不到那一条渠道。
