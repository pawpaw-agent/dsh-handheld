**一次逻辑审计的收口版：50 条问题全修 + 后台通知终于可靠。** 全部改动都在真机
（SM-S9280 / Android 16）上逐条验过。

## 🔔 「离开手机一会儿就收不到通知」—— 真因找到了

这个毛病从项目早期就在（你报过两次）。今年的真机取证把它钉死在**页面之外**：

- 退到后台 **30 秒内**结束的那一轮，通知正常；
- 退到后台 **3 分钟以上**的那两次，日志里**一条心跳都没有** —— 页面根本没在渲染。
  WebView 的渲染是**独立子进程**，不可见时会被系统标成 `WPRI`（waived priority）并冻结，
  JS 停跑、DOM 不再更新；`setRendererPriorityPolicy(IMPORTANT, false)` 实测也救不回来。

所以通知改成从 **Host 自己发的权威状态**取：App 直接订阅
`/api/remote.mux` 的 `$events` 流（认证用 WebView 已经换好的 cookie），收到

```
{"type":"emit","event":"api-session/status","args":["session-…", false]}
```

就发通知 —— 它来自 App 自己的进程（有前台服务，不会被这样冻），**与页面无关**。
页面那条快路径保留（活着时更早更准），两条路按「轮」对齐去重，同一轮只响一次。

实机验证（App 在后台）：

```
22:35:27.928  DshEvents : Host 报告回合状态：session=… running=false
22:35:27.929  DshApp    : 事件流报告回合结束（…，前台=false）
22:35:27.942  DshNotifier: 已发任务完成通知：…
```

顺带撤掉了两处为此试过、但证明无效的改动（保留 renderer 不被 waive、后台不暂停定时器），
省电策略回到原样。

## 🧭 主机身份变了不再是死路

`dbclient -y` 只放行**未知**主机；电脑重装 / 容器重建 / DHCP 把同一 IP 分给别的机器之后，
旧指纹会让连接被直接拒绝 —— 而 `known_hosts` 在应用私有目录里，此前只能**清应用数据**
（配置一起丢），提示还是「检查地址/账号/密码」，把人引向完全错误的方向。

现在：连接失败会**按原因给话**（身份变了 / 私钥格式不对 / 认证被拒 / 端口没监听 / 网络不通），
并在「连接设置」末尾给了「**重置已信任的电脑身份**」——手机端唯一的出路。

## 🧪 审计 50 条一起收口

这一版把一轮完整逻辑审计（隧道与进程 / 连接屏与生命周期 / 终端与测试台 / 凭据·通知·诊断 /
注入插件 / CI 与验证脚本，六路并行 + 逐条复核）的 50 条全部修掉，其中值得一提的：

- **永久连不上**：连接中「断开连接」漏放连接守卫 → 主按钮此后只会回「正在连接中，请稍候…」；
- **凭据进日志**：带 token 的 URL 会被打出来（WebView 的当前 URL 就是它）→ 现在在日志唯一收口处
  统一打码成 `token=***`；
- **CI 可能签出「假正式包」**：签名 secrets 只配一半时 CI 不告警、用仓库里公开的调试密钥签；
  现在判据与 Gradle 逐项对齐，并断言「正式签名不得是那把调试证书」；
- **host key 不匹配 / 生成私钥的线程没有异常兜底 / 终端会话结束没有重连入口 /
  切一次登录方式会抹掉另一种凭据 / 诊断页读不到上一代日志 / 明文 HTTP 是全应用开关**…… 各自修掉，
  详情见 `docs/logic-audit-2026-09-17.md`（含每条的机理、触发条件、修法与真机证据）。
